# AI paradoxes: a correct check of an incomplete document

The clearest tension in this homework is that the verifier passed all seven public CVs and still accepted the adversarial CV. These results are compatible. The public test showed that the agent could identify discrepancies in the text it received. The adversarial test exposed a different weakness: some visible content never reached the agent.

Kelly Tsang's adversarial CV includes Python as a skill, although her mock LinkedIn profile does not list it. The skills row is an image inside the PDF. The text loader omitted that row, and the verifier returned 0.90, explaining that the CV listed no skills. Its explanation was consistent with its input, but incomplete as an assessment of the actual document. A detailed explanation can therefore make a decision look more reliable without revealing what the system failed to see. Checking the reasoning alone would not have caught this problem; comparing the rendered document with the extracted text would have.

There is also a tension between reliability and automation. The agent uses timeouts, output recovery and a fallback score so that one failed response does not stop the whole batch. This makes the program more dependable operationally. However, a completed run is not necessarily a completed verification. In the assignment, the fallback score of 0.5 falls on the discrepancy side of the classification threshold, even when the actual issue is uncertainty or a technical failure. In a practical verification workflow, those cases should remain distinguishable from a confirmed false claim. Otherwise, keeping the process running could hide the need for further review.

The defender-and-attacker structure of the homework reveals another tension. The same tools that help build a verifier also make it easier to test how that verifier can fail. In this controlled exercise, the attack provides useful evidence about an input-processing weakness. Its success is not a reason to trust the attacker more; it is a reason to inspect the boundary between the document and the model. Stronger instructions about ignoring malicious content would not recover a skill that was never extracted.

The practical lesson is to evaluate the whole workflow. The 7/7 result measures performance on a small public set, while the attack tests a different condition. Neither result should be stretched beyond that scope. A stronger system would check whether extraction preserved meaningful visible content, route uncertain cases for review and keep evidence of which claims were actually compared. Even OCR would need testing rather than being assumed to solve the problem. The important question is not only whether the agent's answer sounds justified, but whether it had the information needed to justify that answer.
